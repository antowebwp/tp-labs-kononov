Условия эксперимента

Можно запускать. Для больших наборов потребуется больше времени.

Генератор Random(42): одинаковые исходные данные. Во время замера лучше не запускать другие тяжёлые программы.

Время и выделенная память по этапам

Таблица заполнится после замера.

«Память» — суммарные выделения объектов во время этапа, а не пиковое потребление RAM. Сравнение результатов выполняется вне измеряемого участка. Итоговое время — сумма времён четырёх этапов.

01 · Уникальные покупатели

List.Contains заново просматривает список. HashSet проверяет наличие быстрее; отдельный список сохраняет исходный порядок покупателей.

02 · Текстовый отчёт

Конкатенация пересоздаёт длинную строку на каждом шаге. StringBuilder накапливает текст в буфере и создаёт итоговую строку один раз.

03 · Сортировка сумм

Пузырьковая сортировка делает O(n²) сравнений. List.Sort использует сортировку с O(n log n) в худшем случае.

04 · Расходы покупателей

Вместо полного просмотра покупок для каждого человека Dictionary накапливает суммы за один проход.

Профилирование на Mac

В README есть команды dotnet-trace для записи управляемых стеков до и после. Это отдельный кроссплатформенный способ профилирования; графики выше показывают замеры Stopwatch.
