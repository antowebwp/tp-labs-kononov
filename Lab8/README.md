# Lab8 — оптимизация, веб-версия для Mac

Из общей папки «Готовые лабораторные»:

```text
dotnet run -c Release --project Lab8/Lab8.csproj
```

Откройте http://127.0.0.1:5088. Ctrl+C останавливает сервер.

На странице задаются 100–100000 покупок и 1 либо 3 повторения. Есть прогресс по этапам, отмена, сравнение результатов, графики времени, таблица выделений памяти и экспорт CSV. Кнопка «Готовый замер» показывает сохранённый реальный замер, а не запускает новый.

Выполняется только один замер одновременно. Незавершённый расчёт можно отменить; после обновления страницы браузер снова подключается к активному расчёту. Хранятся состояния последних восьми запусков.

## Что оптимизируется

Исходная задача взята из текущей методички: Random(42), имена user0–user4999 и суммы от 1 до 9999. Старая Lab8 из Downloads сравнивала тригонометрические калькуляторы и не соответствовала этому заданию.

1. Baseline.Unique: List.Contains для каждого покупателя → Optimized.Unique с HashSet и отдельным списком для сохранения порядка. O(n × m) → O(n) в среднем.
2. Baseline.Report: string += с копированием растущей строки → StringBuilder. O(n²) → O(n) при ограниченной длине одной записи.
3. Baseline.Sort: пузырьковая сортировка → List.Sort. O(n²) → O(n log n).
4. Baseline.Totals: полный проход для каждого покупателя → Dictionary и один проход. O(n × m) → O(n + m) в среднем.

Проверяются полные списки уникальных покупателей с порядком, весь текст отчёта, все отсортированные суммы и все пары «покупатель — итог». При равных суммах порядок лидеров сохраняется. Чётная медиана, как в методичке, берётся по индексу Count / 2.

## Измерения

Stopwatch измеряет синхронные участки на одном рабочем потоке. GC.GetAllocatedBytesForCurrentThread показывает суммарные выделения объектов, а не пиковую RAM. Подготовка данных и проверка результатов не входят в замеры этапов. Итог — сумма времён этапов; при трёх повторениях это сумма медиан.

Перед измерением обе версии прогреваются на 100 покупках. Порядок «до/после» чередуется между повторениями. Время зависит от нагрузки, версии .NET, JIT и GC; ручные замеры не заменяют BenchmarkDotNet. HashSet и Dictionary могут выделять больше памяти, чем исходные коллекции.

Сохранённый замер: 2026-11-27T18:22:37.246946+07:00, macOS ARM64, Release, .NET 10, N=30000, медиана трёх повторений.

| Этап | До, мс | После, мс | Ускорение | Изменение |
| --- | --- | --- | --- | --- |
| Уникальные покупатели | 216.400 | 1.244 | 173.89× | List.Contains → HashSet |
| Текстовый отчёт | 2040.025 | 0.654 | 3119.78× | string += → StringBuilder |
| Сортировка сумм | 1653.017 | 2.192 | 753.94× | Пузырьковая → List.Sort |
| Расходы покупателей | 781.929 | 3.266 | 239.43× | Вложенные циклы → Dictionary |

Контрольные результаты: 4986 покупателей, 409941 символ в отчёте на macOS с LF, медиана 4992, лидер user1846, его сумма 93997. JSON замера хранится в Measurements/reference.json. Переводы строк зависят от ОС, но обе версии на одной ОС используют одинаковый Environment.NewLine.

## Профилирование на Mac

```text
bash Lab8/profile.sh
```

Скрипт собирает Release, восстанавливает закреплённый локальный инструмент dotnet-trace и записывает artifacts/before.nettrace, artifacts/after.nettrace и файлы Speedscope, а также top-функции в текстовом виде. Сырые nettrace исключены из Git. На странице скачиваются новые файлы Speedscope из artifacts, а если их ещё нет — сохранённые контрольные профили из Measurements/Profiles. Поэтому просмотр контрольных профилей работает и после клонирования репозитория.

Исходная версия профилируется один раз на 30000 покупках, оптимизированная — 200 раз для получения достаточно длинной выборки. Поэтому длительности и проценты этих трасс не являются прямым сравнением времени одного запуска. Время каждого этапа отдельно измерено в таблице выше.

Методичка требует Visual Studio Performance Profiler и скриншоты CPU Usage. Здесь вместо него применяется кроссплатформенный dotnet-trace/EventPipe с выборкой управляемых стеков. Это не идентичный отчёт Visual Studio и не обещание, что преподаватель примет замену без согласования. Измерения Stopwatch, тесты и трассы работают на Mac.

Документация инструмента: https://learn.microsoft.com/en-us/dotnet/core/diagnostics/dotnet-trace

## Структура и проверки

- Program.cs — веб-API и локальный сервер; wwwroot — страница.
- Optimization/Baseline.cs — сохранённые исходные алгоритмы.
- Optimization/Optimized.cs — четыре независимые оптимизации.
- BenchmarkEngine.cs — замеры времени, выделений и эквивалентности.
- RunService.cs — один фоновый расчёт, прогресс, отмена и ограниченная история запусков.
- Lab8.Tests — 18 тестовых случаев.

```text
dotnet test Lab8/Lab8.slnx -c Release
dotnet run -c Release --project Lab8/Lab8.csproj -- --benchmark --count 30000 --repetitions 3
```

В истории Git есть исходная версия, измерительная инфраструктура и отдельные коммиты для каждой из четырёх оптимизаций с фактическими замерами. Конечные алгоритмы не обращаются к Console и не зависят от браузера.
